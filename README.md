# LaserCost — DXF-калькулятор лазерной резки

## Цель
Веб-калькулятор для предварительного расчёта машинного времени и стоимости лазерной резки по DXF-раскладке.

## MVP: входные данные
- DXF-файл раскладки.
- Материал: чёрная сталь, нержавеющая сталь, алюминий.
- Толщина материала.
- Мощность лазера.
- Вспомогательный газ с фильтрацией применимых режимов.
- Редактируемые режимы резки: скорость, время прокола и параметры вспомогательных операций.
- Стоимость машинного часа.
- Учёт стоимости листа либо режим «материал заказчика».

## Геометрический анализ
- Поддержать линии, окружности, дуги, полилинии, эллипсы и сплайны.
- Рассчитать длину реза с учётом дуг и bulge сегментов полилиний.
- Обнаруживать замкнутые контуры, открытые контуры и возможные дубликаты/пересечения.
- Показывать предпросмотр и диагностировать единицы/масштаб DXF.
- Явно сообщать об объектах, которые не удалось разобрать.

## Модель времени
Отдельно показывать:
1. Чистое время резки по длине и скорости.
2. Время проколов/врезок по количеству и режиму.
3. Оценку холостых перемещений.
4. Поправку на динамику головки, разгон/торможение и вспомогательные задержки.
5. Итоговое оценочное машинное время.

Обычный DXF часто не содержит CAM-порядок обработки и реальные траектории перемещений. Поэтому без CAM-файла часть значений остаётся оценкой. Интерфейс должен отличать геометрию, извлечённую из DXF, от расчётных допущений.

## Стоимость
- Стоимость обработки = оценочное машинное время × тариф машинного часа.
- Стоимость материала добавляется только по выбору пользователя.
- Итог и составляющие показываются отдельно.
- В дальнейшем добавить отходы/использование листа, газ, электричество, расходники, операторские и накладные расходы — только по запросу.

## Этапы разработки
1. MVP-интерфейс и загрузка DXF.
2. Надёжный геометрический парсер, единицы и проверка на реальных раскладках.
3. Редактируемая технологическая база по материалу/толщине/мощности/газу.
4. Более реалистичная оценка проколов и холостого хода.
5. Сопоставление расчётов с фактическим временем станка и калибровка.
6. Экспорт расчёта/коммерческого предложения и удобное сохранение настроек.

## Критерии качества
- Не выдавать оценочные числа за точные CAM-данные.
- Не подставлять непроверенные режимы как производственные рекомендации.
- Показывать ошибки и ограничения DXF понятным языком.
- Проверять результаты на реальных файлах и фактическом времени станка.
- Мобильный и настольный интерфейс, без обязательной регистрации для базового расчёта.

## Текущее состояние
Создан начальный интерфейсный прототип. Таблица скоростей пока демонстрационная и не является валидированной технологической базой. Оценка холостых перемещений предварительная; её нужно заменить/калибровать на реальных данных.

## Импорт файлов — статус разработки

LaserCalc должен поддерживать три сценария:

1. **Готовый раскрой CypCut/CypNest** — пользователь загружает один или несколько файлов раскроя.
2. **Набор деталей** — пользователь загружает несколько DXF и задаёт количество каждой детали.
3. **Простая раскладка** — пользователь задаёт количество, размеры листа, зазор и разрешённый поворот; сервис размещает детали и оценивает отходы.

### Форматы CypCut/CypNest

| Расширение | Назначение по документации BOCHU | План поддержки |
|---|---|---|
| `.dxf` | Геометрия детали/раскроя; экспорт раскроя DXF не содержит технологических данных | Парсинг геометрии и предварительный расчёт |
| `.lxd` | Файл технологической траектории/раскладки в старых и совместимых версиях | Исследовать структуру на реальном образце |
| `.lxds` | Один результат раскладки в одном файле; поддерживается CypCut новых версий | Исследовать структуру на реальном образце |
| `.nrp` | Пакет заданий с несколькими результатами раскладки для старых версий | Исследовать контейнер и доступность траекторий |
| `.nrp2` | Пакет заданий с несколькими результатами раскладки для новых версий | Исследовать контейнер и доступность траекторий |
| `.nsds` | Внутренний формат задания CypNest | Не включать в MVP без образца и подтверждённого способа чтения |
| `.pdf` | Отчёт/распечатка, если пользователь экспортировал её из ПО | Позже: извлечение табличных данных; не считать заменой траектории |
| `.zip` | Контейнер, не самостоятельный формат раскроя | Позже: распаковка и распознавание вложенных файлов |

Официальные материалы:
- BOCHU, [Import Drawing](https://www.bochu.com/tutorials/basics-import-drawing/)
- BOCHU, [Export File for Laser Production](https://www.bochu.com/tutorials/export-file-for-laser-production/)
- BOCHU, [CypNest — export DXF layouts and parts](https://www.bochu.com/tutorials/cypnest-how-to-export-dxf-layouts-parts/)

**Текущий прототип:** принимает несколько DXF, позволяет задать количество для каждого файла и рассчитывает суммарную оценку по поддерживаемой геометрии. Расширения LXD/LXDS/NRP/NRP2 распознаются, но их содержимое пока не декодируется. Нельзя сообщать пользователю, что технологические данные этих форматов уже извлекаются.

### Предварительная база режимов резки

Файл `data/cut-modes.json` содержит первую нормализованную таблицу ориентировочных скоростей для волоконного лазера 3 кВт:
- чёрная сталь + кислород;
- нержавеющая сталь + азот;
- алюминий + азот;
- диапазоны скорости, среднее значение, источник и уровень уверенности.

**Важное ограничение:** подробные числовые строки Laser Legend / LaserLandServis (`https://laserlandservis.ru/cutmodes`) не удалось автоматически извлечь в этой сессии. Поэтому текущая таблица не выдаётся за среднее по LaserLandServis: она собрана из доступных опубликованных справочных таблиц и содержит низкоуверенные значения. Её нельзя использовать как производственные рекомендации без проверки. Следующий шаг — импортировать исходные строки LaserLandServis и свести совпадающие режимы по материалу, толщине, мощности и газу.

Источники текущей стартовой таблицы:
- [Laser Legend / LaserLandServis](https://laserlandservis.ru/cutmodes) — основной запрошенный источник, требует ручного/технического импорта числовых строк.
- [Механит — таблица подбора мощности](https://mehanit.ru/press/tablica-podbora-moschnosti-lazernogo-istochnika)
- [ГОСТ Р 72479-2025 — справочные скорости](https://normadocs.ru/gost_r_72479-2025)
- [LaserGU — параметры резки](https://lasergu.ru/novosti-akcii/parametry_lazernoy_rezki_metalla/)
- [СпецЭлектродСервис — режимы резки толстого металла](https://ses24.ru/about/expert-articles/lazernaya-rezka-tolstolistovogo-metalla.html)

### Следующие технические этапы

1. Получить реальные обезличенные образцы LXD/LXDS/NRP/NRP2 из CypCut/CypNest и зафиксировать версии ПО.
2. Определить контейнер/кодировку и извлекаемые данные; не полагаться только на расширение файла.
3. Построить нормализованную модель раскроя: листы, детали, контуры, технологические операции, пробивки, быстрые перемещения и режимы.
4. Сопоставить оценку со временем CypCut и фактическим временем HSG 3000 W.
5. Реализовать раскладку DXF-деталей по листам отдельно от импорта готовой программы.


## Проверка реальных образцов CypCut

Файл `data/cypcut-samples.json` хранит метаданные, вручную извлечённые из двух предоставленных пользователем LXDS-контейнеров:

- `23 copy.lxds`: CypCut 6.3.907.11, 10 мм в документе, в заметке режима указана скорость 0,8 м/мин и давление 0,6 bar. В самом файле есть противоречия между названием режима, толщиной, соплом и фокусом — запись помечена как кандидат для проверки, не как подтверждённый режим HSG.
- `5мм 2 листа заказ почта базис.lxds`: два раскроя 1500×3000 мм, 96 и 275 деталей; заполнение 88,67% и 75,11%; всего 371 деталь по инвентарю. Сохранённый режим содержит несоответствия между именем файла, толщиной и названием материала.
- В извлечённых метаданных нет подтверждённого времени обработки/резки. Поэтому пока нельзя честно рассчитать ошибку калькулятора относительно времени CypCut или станка.
- Контейнеры LXDS — ZIP с XML и бинарными блоками геометрии. Сам факт успешного чтения XML не означает, что геометрия, порядок резки и холостые перемещения полностью декодированы.

Следующий этап калибровки: получить время обработки, показанное CypCut для каждого результата раскладки, а затем сравнить с фактическим временем резки на станке. Отдельно фиксировать материал, толщину, газ, сопло и реально использованный режим. До такой сверки эти данные не использовать как эталон машинного времени.


### Геометрическая длина реза по двум образцам

По бинарной геометрии первого файла и XML/блокам второго выполнен предварительный подсчёт контуров:

- `23 copy.lxds`: один чертёж — около **1,611 м** (наружный контур + 6 окружностей). При скорости из заметки 0,8 м/мин чистое время резки составляет около **2,01 мин**. Количество копий не домысливалось.
- `5мм 2 листа заказ почта базис.lxds`: суммарно около **204,639 м** контуров для 371 детали на двух листах. При скорости из заметки 2,5 м/мин чистое время резки составляет около **81,86 мин (1 ч 22 мин)**.
- Это время получается только как длина контура / скорость. Оно не включает проколы, врезки, замедление на углах, разгон/торможение, холостые перемещения и ожидания.
- Во втором файле сохранённый режим противоречив: заметка указывает 2,5 м/мин, но в `CamParams` записано `WorkSpeed=48.333`; название режима указывает на 5 мм/воздух, а `MaterialParams` — на 4 мм/холоднокатаный лист. Поэтому 81,86 мин — сценарная оценка, а не подтверждённое время станка.
- Результаты сохранены в `data/cypcut-samples.json`. Дальше нужно сравнить их с временем, показываемым CypCut, и фактическим временем резки.
